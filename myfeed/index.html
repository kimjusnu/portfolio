농가가 쓰는 화면을, 가볍고 읽기 쉽게.

마이피드는 2026년 7월 기준 130여 농가가 사용하는 사료 관리 웹서비스입니다. 웹 개발과 운영을 맡아 농장 모니터링 화면, 관리자, 웹 알림을 만들고 고쳐 왔습니다.

담당 역할
모니터링 화면·관리자·웹 알림 구현, 권한 계층, 요청 수 줄이기, 공통 UI 정리, 언어팩 전환, 재학습용 라벨링 화면.
함께 일한 사람
앱 담당자와 요구사항·화면을 함께 정리했습니다.
Stack
FastAPI · Jinja2 · JavaScript

01 · 화면 개선

문의에서 시작해, 화면에서 끝냅니다.

  • 메뉴를 찾기 쉽게 고객 문의에서 메뉴를 찾기 어렵다는 점을 확인하고, 주요 작업으로 가는 경로와 화면 가독성을 조정했습니다.
  • 한 곳에서 고치는 공통 UI 여러 페이지에 복제돼 있던 공통 UI를 한 곳에서 수정할 수 있게 정리했습니다.
  • 언어별 키·값 문구 화면 문구를 언어별 키·값으로 관리하도록 바꿔, 번역 API 응답을 기다리던 흐름을 개선했습니다.
  • 계정마다 다른 표 컬럼 회사·대리점·농장 계정마다 필요한 컬럼이 달라, 권한 클래스로 표시할 컬럼을 나누고 1350px 이하에서는 핵심 컬럼만 남겼습니다. 세로로 길던 표는 페이지로 나눴습니다.
  • 목록과 상세의 순서 맞추기 목록의 정렬 순서와 상세 화면의 화살표 이동 순서가 달랐습니다. API 쪽 재정렬로 풀리지 않자, 화면에 실제로 그려진 순서를 브라우저 저장소로 넘겨 상세 화면이 그 순서를 따르게 했습니다.
  • 깜빡이던 툴팁 이미지 차트 툴팁의 이미지를 바로 바꿔 끼우던 방식을, 미리 불러온 뒤 교체하도록 바꿔 깜빡임을 없앴습니다.
  • 장애 디바이스 보고서를 한 번에 AI 브라우저로 농장별 장애 현황을 모으던 시도가 데이터가 많은 계정에서 막히자, 관리자 API를 병렬로 모아 엑셀 보고서로 바로 내려받는 기능으로 방향을 바꿨습니다.

02 · 요청 줄이기

느린 구간을 먼저 찾고, 그다음에 줄였습니다.

구간별 소요시간 로그로 느린 구간을 찾고, 사진 지연 로딩과 중복 호출 정리로 요청을 줄였습니다. 운영에는 공통 스크립트 제거만 반영됐습니다.

03 · 알림

목적이 다른 두 폴링, 반대 정책.

안 읽은 알림 개수

화면을 안 볼 때는 멈춤

폴링 1회당 요청을 6개에서 1개로 줄이고, 숨은 탭에서는 멈추게 했습니다.

푸시가 끊겼을 때를 대비한 조회

숨은 탭에서도 유지

특정 브라우저에서 알림이 표시되지 않는 현상을 다른 브라우저와 비교하며 범위를 좁혔고, 이 조회는 계속 돌도록 두었습니다.

한 브라우저에서만 알림이 뜨지 않았을 때

  • 증상 Edge 151에서 웹 푸시가 서비스 워커까지 도착하지 않아 알림이 뜨지 않았습니다(2026.08).
  • 비교 같은 알림이 다른 브라우저에서는 뜨는 것을 확인해, 서버가 아니라 브라우저 쪽 문제로 범위를 좁혔습니다.
  • 판단 브라우저 내부 원인을 파고들기보다, 사용자에게 알림이 도착하게 하는 것을 먼저 해결했습니다.
  • 조치 폴링에서 안 읽은 개수가 늘면 보이는 탭에는 화면 안 알림을, 숨은 탭에는 OS 알림을 띄웠습니다. 푸시와 폴링이 겹쳐도 같은 tag와 알림 번호 기록으로 중복 표시를 줄였습니다.
  • 한계 원인은 확인하지 못했습니다. 이 보완은 페이지가 열려 있을 때만 동작합니다.

04 · AI 결과 화면

AI가 낸 결과를, 사람이 판단할 수 있게.

  • 보조 시각화 도넛 그래프의 퍼센트만으로는 상태를 판단하기 어렵다는 고객 반응을 바탕으로, 사료빈 모양의 2D 그림과 촬영 사진을 나란히 보여 주는 보조 시각화를 만들어 2개 농장의 웹·앱에 시범 적용했습니다. 웹과 앱이 각자 계산해 값이 달라질 수 있어, 계산을 서버로 옮기는 일을 다음 과제로 남겼습니다.
  • 버려지던 이미지를 학습 데이터로 모델이 분할에 실패해 버려지던 이미지를 사람이 마스크로 다시 라벨링해 재학습에 쓰자고 제안하고, 그 라벨링 화면을 만들었습니다. 원형·다각형으로 영역을 고치는 Canvas 편집기, 이미지 크기와 상관없이 0~1로 정규화한 좌표 저장, 재학습 요청 뒤 진행 상태를 배지로 보여 주는 흐름입니다. 라벨링한 이미지는 실제 재학습에 쓰였고, 지금은 모델이 스스로 분류하도록 바뀌어 이 방식은 더 쓰지 않습니다.

05 · 에임비랩 · 회사 홈페이지

투자자(IR) 중심 사이트에서, 고객 문의로 이어지는 사이트로.

투자자(IR) 중심으로 짜인 회사 홈페이지를 고객이 도입 문의까지 이어지는 구조로 개편하는 계획을 세우고, 기획·디자인·구현까지 맡았습니다.

  • IR 중심에서 고객 전환형으로 회사 연혁·수상 같은 회사 소개 위주의 여러 페이지를, 마이피드 기능과 도입 문의 중심의 한 페이지로 바꿨습니다.
  • 사업팀에 바로 닿는 문의 도입 문의를 서버에서 검증한 뒤 사업팀 Flow 업무로 등록되게 연결했습니다. 이렇게 마련한 문의 접점은 사료회사와의 거래 성사에 기여했습니다.
  • 데이터로 판단하기 GA4 이벤트 27개를 정의해 문의 폼 제출과 연락처 클릭을 추적했고, 분석에서 홈페이지 유입 대부분이 모바일이고 체류가 짧다는 점을 확인했습니다. 리뉴얼 계획에는 배포 뒤 볼 지표(방문, 이탈, CTA 클릭, 문의 제출 등)를 먼저 정해 두었고, 봇 트래픽은 성과 지표에서 빼되 원천 데이터는 Clarity에 남기는 기준을 세웠습니다.

수치와 범위에 대해
  • 알림 요청 수는 변경 커밋에서 확인하고 운영에 반영된 값이고, 모니터링 화면 요청 수(98→50)는 스테이징에서 잰 값입니다. 모든 사용자 환경의 체감 속도를 잰 값은 아닙니다.
  • 보조 시각화는 2개 농장에 시범 적용한 단계입니다. 시각화가 잔량 추정의 정확도를 높이지는 않습니다.
  • 사내 서비스라 공개 링크는 없습니다.
  • 화면은 시험용 계정으로 찍었고, 실제 농가 정보는 담지 않았습니다.
